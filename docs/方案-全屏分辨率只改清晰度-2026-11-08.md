# 方案：全屏状态下改分辨率 = 只改清晰度，不改窗口

- 日期：2026-11-08
- 状态：**已实装**
- 起因：玩家反馈「全屏状态下改分辨率会留一大个黑边」（附截图）

---

## 一、现象与证据

截图（1280×708，含任务栏与桌面）逐像素量出来：

| 项 | 实测 |
|---|---|
| 游戏窗口内容区 | x[0,465] · y[12,361] ⇒ **466 × 350** |
| 内容长宽比 | 466 / 350 = **1.331（= 4:3）** |
| 窗口外 | 桌面（右侧 814px、下方 346px 全空） |

466×350 的 4:3 比例与档位表里的 **1400×1050** 完全对应（4:3 档只有
`1920×1440` / `1856×1392` / `1792×1344` / `1600×1200` / `1400×1050` 五个，
最小那个正是 1400×1050）。⇒ **玩家点了一个 4:3 档，窗口被真的缩成那个尺寸。**

## 二、根因

`EveResolution.apply_index()` 在**任何**情况下都做三件事：

```gdscript
if win.size != want: win.size = want     # ① 改窗口尺寸
_center(win)                             # ② 在屏幕可用区居中
```

而玩家当时把窗口**最大化**了（看起来就是全屏）。Windows 上对最大化窗口写
`size` 会**先把窗口 un-maximize、再 resize** —— 这是 OS 行为，不是 Godot 的
bug，也没有 flag 能关掉。于是：

```
最大化窗口(2560×1369) --点了 1400×1050 档--> 窗口(1400×1050) + 退出最大化
                                          ⇒ 右侧 1160px / 下方 319px 露出桌面
```

## 三、修法

**全屏 / 最大化时，分辨率档不再回答「窗口该多大」这个问题 —— 它改的是渲染精度。**

```
apply_index(win, idx):
    ├─ is_screen_filled(win) == true  → apply_render_scale(win, idx)   # 只写 scaling_3d_scale
    └─ 否则                            → reset_render_scale + 改窗口尺寸 + 居中（原行为）
```

`is_screen_filled()` 认三种模式，**漏一个就漏一条黑边路径**：

| 模式 | 为什么必须认 |
|---|---|
| `MODE_MAXIMIZED` | **玩家实际最常遇到的那个**（标题栏最大化 / 双击标题栏 / Win+↑）。它看起来就是全屏，但写 size 会退出最大化 |
| `MODE_FULLSCREEN` | 无边框全屏。引擎会忽略 size 写入，但别去写：某些平台上写 size 会把模式悄悄切回窗口化 |
| `MODE_EXCLUSIVE_FULLSCREEN` | 独占全屏。同上，而且改尺寸容易黑屏一下 |

### 3.1 「清晰度」具体改的是什么

`Viewport.scaling_3d_scale`：

```
scale = min(档宽 / 画面宽, 档高 / 画面高)   夹到 [0.25, 2.0]
```

- `scale < 1` ⇒ 3D 按更低分辨率渲染再放大 ⇒ 省 GPU，画面略糊；
- `scale > 1` ⇒ 超采样（4K 档跑在 1080p 全屏上），更干净但更贵。

**用 min 而不是面积比**：4:3 的档落在 16:9 的屏上时，按面积算会得到比宽度
方向更低的倍率 ⇒ 画面糊得比玩家选的那档还过头。

### 3.2 两条必须写明的边界

1. **只作用于 3D。** 2D 的 HUD / 面板永远按窗口原生分辨率画，文字始终清晰。
   这是刻意的：分辨率档在这里的用途是「画质 / 性能」，不是「放大缩小文字」
   （那是字号滑杆的活）。
2. **只在 Forward+ / Mobile 后端成立。** 本工程桌面端没设
   `renderer/rendering_method` ⇒ 默认 `forward_plus` ✔。移动端走
   `gl_compatibility`，但那里 `is_enabled()` 本来就是 false（安卓全屏、没有可调
   余地），不受影响。

### 3.3 从全屏退回来

两个都做，缺一个就会留下「退出最大化后画面还是糊的」：

- 窗口模式分支里 `reset_render_scale()`（下次 apply 就归位）；
- `apply_from_settings()` 给根窗口挂**一次** `size_changed`（`has_meta` 挡重），
  还原尺寸时立刻复位。

⚠️ 钩子里**只复位精度、不套用档位尺寸**：玩家刚手动把窗口拉成某个大小，
这时候再按档位改一次尺寸，就是"我刚拖好你又改回去"。

### 3.4 设置窗的文案

全屏时说明行从「★ = 推荐档 · 自适应 = 跟随屏幕」换成
**「全屏中：只调 3D 清晰度」**。

不写这一行，玩家点完发现窗口没变、画面只糊了一点，会判定成**按钮坏了**
（红线 9：不许有"看着能点、实际没反应"的东西）。

## 四、实测（本机 2560×1440，真窗口，非无头）

| 步骤 | 结果 |
|---|---|
| 最大化后 `win.size` | `(2560, 1369)` —— 是**最大化后的客户区**（扣掉 71px 任务栏）✔ 可以直接当分母 |
| 全屏下选 1920×1080 | `scale = 0.7500`（= min(1920/2560, 1080/1369)）· `win.size` **仍是 (2560, 1369)，一像素没动** |
| 退出最大化 | `scale` 立刻回 `1.000`（钩子生效）· 窗口回到还原尺寸 `(2048, 1152)`，**没有被档位顶掉** |

纯逻辑断言（`Window.new()` 未入树，纯属性读写）：

| 断言 | 实测 |
|---|---|
| 默认 WINDOWED ⇒ 不算全屏 | ✔ |
| MAXIMIZED / FULLSCREEN / EXCLUSIVE_FULLSCREEN ⇒ 算全屏 | ✔ 三个都认 |
| 全屏分支改精度时 size 不变 | ✔ |
| 1366×768 档 / 1920×1080 画面 | `0.7111`（= 768/1080，高度方向更紧）✔ |
| 4K 档 / 1920×1080 画面 | 夹到 `2.0000`（超采样上限）✔ |
| `reset_render_scale` | `1.0000` ✔ |

- [ ] 最大化状态选 1366×768 ⇒ 战场 3D 明显变糊（省 GPU），HUD 文字仍清晰
