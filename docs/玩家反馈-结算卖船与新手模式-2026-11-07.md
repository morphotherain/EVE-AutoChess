# 玩家反馈：结算期卖船 / 买船看属性 / 新手模式（去倒计时）

> 2026-11-07 立档。**当前状态：三条全部落地，版本号 `0.14.10.5.38`。**

## 零、三条需求原文

1. 「有玩家反馈，在一回合结算时，需要能够卖船，不然怕不够钱打捞想要的船」
2. 「买船的时候，需要可以直接点开看船的属性」
3. 「针对所有难度的任务关卡，正式进入游戏时，需要自己选择是否进入新手模式，
   新手模式将不再进行倒计时，即取消所有倒计时，让玩家决定什么时候开战、
   什么时候进入下一阶段，战斗倒计时取消后，只有战场上分出胜负后才会结束。」

两条交互口径由用户拍板：

- 买船看属性 → **「点一下看档案，再点一次买」**（不是长按、不是右键）
- 新手模式问几次 → **「每次从菜单开新局问一次」**（局内重开不再问）

## 一、结算期卖船

### 1.1 真因：能力早就有，玩家发现不了

`EveRunState.can_sell()` 一直是 `PREP or RESOLVE` 放行，拖到商店即卖。
所以这不是"没做"，是**两件事叠在一起**：

| 层 | 现象 | 处置 |
|---|---|---|
| 表层 | 结算期商店被 `set_shop_buy_enabled(false)` 压暗，玩家读作"这里用不了" | 结算期把商店**常亮成橙色出售区** + 一行日志提示 |
| 深层 | **卖了另一艘船**（真 bug） | 结算期改为按条目本体出售，见 1.3 |

提示语（直接中文字面量，不建 i18n key —— `strings.csv` 已冻结）：

> 钱不够打捞？把船拖到下方商店即可出售换星币（结算期有效）

### 1.2 一个必须记住的坑：`set_selling(true)` 会连备战席轨道一起染橙

`EveHudRoot.set_selling(on)` 原来一个参数，同时点亮商店窗和备战席轨道。
但备战席轨道的橙色态文案是「拖到此处出售」，而它的实际落点语义是
**撤回 / 换位** —— 结算期把轨道点亮等于对玩家撒谎。

⇒ 加参数 `set_selling(on: bool, bench: bool = true)`，结算期传 `false`：

```gdscript
hud.set_selling(phase == EveRunState.Phase.RESOLVE, false)
```

`bench = false` 且 `on = false` 时仍会强制收掉轨道的橙条
（否则上一阶段的橙色会残留在轨道上）。

### 1.3 [PITFALL] 结算期卖错船 —— 这是这次改动里唯一的真 bug

```
开战前：field = [A, B, C]          → 拖放控制器记下 index
战斗中：B 阵亡，resolve_battle() 把 B 从 field 里删掉
结算期：field = [A, C]            → 同一 index 现在指向 C
```

`resolve_battle()` 里的 `lost_field` 是**降序删**的，删完 `field` 就整体前移；
而拖放控制器手里的 `index` 来自开战前的映射（`begin_drag()` 里取的）。
⇒ 玩家拖 A 去卖，实际卖掉的是 C。

修法：结算期不走下标，走**条目本体**。新增 `EveRunState.sell_entry()`：

```gdscript
func sell_entry(entry: Dictionary) -> Dictionary:
    if not can_sell(): return _deny("只有准备阶段和打捞结算时能出售")
    if entry.is_empty(): return _deny("这一格是空的")
    for i in field.size():
        if is_same(field[i], entry): return _do_sell(entry, i, false)
    for i in bench.size():
        if is_same(bench[i], entry): return _do_sell(entry, i, true)
    return _deny("这艘船已经不在编队里了")
```

⚠️ 用 `is_same()` 而不是 `==`：**同名同星的船字典值可能完全相同**，
`==` 会匹配到第一艘同款而不是玩家拖的那一艘。

`[WHY]` 只在结算期走本体匹配，准备阶段仍走 `sell_from_field(index)`：
准备期 `field` 不会变，下标是准的，没必要多扫一遍。

### 1.4 第二层坑：卖了船，3D 还站着

拖放控制器只改数据，`EveBattleArena` 里的舰船视觉是独立一份。
⇒ 卖完必须当场收掉，否则玩家看到"扣了船还在场上"。
新增 `_drop_sold_visual(ship_id)`：置 `alive = false` + `_arena.remove_ship_visual(ship_id)`。

另外 `_refresh_run_ui()` 在 `phase == RESOLVE` 时补一次 `_refresh_salvage_area()`，
让"持有 N 星币"在卖船后立刻同步（打捞区是自己的钱数计算源）。

## 二、买船看属性：两段式点击

### 2.1 为什么不长按 / 不右键

- `strings.csv` 冻结 + 移动端唯一事实标准：**手机玩家没有右键，长按不可发现**
- 长按要吃掉拖放的按下事件，会跟现有的 `TAP_SLOP=14.0` 判定打架

⇒ 点第一下**只看不买**（档案窗 + 金边 + 状态栏提示），
点第二下（同一张卡）才真的扣钱。

### 2.2 实现

`EveShop` 新增信号与状态：

```gdscript
signal preview_requested(offer_index: int)
var _armed: int = -1        # -1 = 未选；N = 第 N 张卡已"上膛"
```

`_on_card_input()` 的分支顺序：

```
空槽            → 静默 return（不给假反馈）
_armed == index → _set_armed(-1) + buy_requested.emit(index)   ← 第二下：买
否则            → _set_armed(index) + preview_requested.emit(index) ← 第一下：看
```

`_set_armed()` 同时刷金边（2px）+ 略亮底色，并把状态栏改成
「已选 X · 再点一次购买 ◆N」。

### 2.3 [PITFALL] `_armed` 必须能被三条路清掉

不清就会出现「上次选的还亮着金边，玩家以为已经买了」：

1. `set_offers()` —— 买走 / 刷新 / 进新回合，整排卡换人
2. `set_buy_enabled(false)` —— 进交战/结算，买不了就不该留上膛态
3. 第二下点击本身

另外 `set_bench()` 原来会直接覆写状态栏文本，会把「再点一次购买」冲掉；
改为统一走 `_refresh_status_text()`，由它自己决定显示上膛提示还是常规提示。

### 2.4 预览船怎么造

主控 `_on_shop_preview(index)` 里用 `_fleet.build_preview(offer)` 造一次性 `EveShip`
喂给已有的 `EveShipDossier`（`hud.show_ship()`）。

⚠️ 这个临时船**绝不进 `_own_ships`** —— 那是个 id→EveShip 的注册表，
塞进去会污染后续的视觉映射和出售逻辑。

只允许在 `phase == PREP` 生效：结算期卡是暗的，点它看属性没有意义。

`EveShipDossier` 的空态文案也顺带改了：原来写「战场 / 备战席」，现在加「商店卡」
（因为商店卡现在第一下只预览），并同步 `i18n/strings.csv` 的 `DOSSIER_EMPTY_P`
（en / zh_CN 两列都改）。

## 三、新手模式（去倒计时）

### 3.1 数据结构：做成 `run` 的字段，跟存档走

`EveRunState` 新增（紧跟 `difficulty_id`）：

```gdscript
var novice_mode: bool = false
```

- `start_run()` 里重置为 `false`（新局默认标准节奏）
- `to_dict()` / `from_dict()` 都带上，老存档读不到时默认 `false`（向后兼容）

### 3.2 何时问

`_ready()` 末尾 `begin_prep()` → 改为 `_open_run_or_ask_novice()`。

三重闸门（缺一个就会出事）：

| 闸门 | 挡的是什么 |
|---|---|
| `RUN_STORE.session_active` | 40 多个 `verify_*` 探针不是真实会话，会卡在弹框上 |
| `versus == null` | 联机对局不能被一方暂停 |
| `_novice_asked` | 局内重开（R / 再来一局）是同一局的延续，不该再问 |

重开时用 `keep_novice` 承接：

```gdscript
var keep_novice := run.novice_mode
run.start_run()
run.novice_mode = keep_novice
```

### 3.3 不限时怎么实现

**没有新造一套计时系统**，而是利用顶条的既有语义：

> 顶条倒计时唯一真相源 = `EveCommandBar.time_left / time_total`；
> `tick()` 见到 `time_left <= 0` 直接 `return` ⇒ 永远不会广播 `timer_expired`。

⇒ **传 0 秒 = 不限时**。三处阶段各传一次：

| 位置 | 改动 |
|---|---|
| `begin_prep()` | `hud.set_stage(node, label, 0.0 if _untimed() else PREP_SECONDS)` |
| `eve_phase_battle.start()` | `_hud.set_stage(..., 0.0 if untimed else limit)` |
| 事件节点 | 本来就是 0，不需改 |

判断入口收成一个函数，避免散落：

```gdscript
func _untimed() -> bool:
    return run != null and run.novice_mode and versus == null
```

联机再挡一次：`novice_mode` 在联机入口压根不会被置真（弹框不弹），
`versus == null` 是第二道保险。

### 3.4 模拟器：只关"安全网"，不关收敛机制

`EveBattleSimulator` 新增 `no_timeout`：

```gdscript
elif not no_timeout and elapsed >= time_limit_seconds() * HARD_STOP_MULT:
```

⚠️ **只关 `HARD_STOP_MULT`（3 倍时限强制收场）这一道安全网。**
`set_time_limit()` 仍然照常调用 —— 它是火力渐增曲线（`SUDDEN_DEATH_FRACTION=0.45`
起算、`OVERTIME_RAMP=0.75`、`SUDDEN_DEATH_MAX_MULT=5.0`）的**基准**，
不设就没法算"什么时候开始放大伤害"。

⇒ 不限时局仍然会自动收敛：火力一直涨到一方被打完。
新手模式的语义是「你自己决定何时开战」，不是「永远打不完」。

`check_sudden_death()` 的文案分成两条：

| 模式 | 文案 |
|---|---|
| 限时 | 「火力渐增 —— 伤害开始放大，或时限归零时判定」 |
| 不限时 | 「火力渐增 —— 伤害开始放大，直到一方被击毁（本局不判超时）」 |

### 3.5 [PITFALL] 弹框期间倒计时会自己跑完

`EveCommandBar.time_left` 默认 24 秒，以前由 `begin_prep()` 立刻覆盖。
现在开局被弹框挡了一下 ⇒ 那 24 秒会真的开始走，玩家还在读弹框就判负了。

两道保险：

1. `_open_run_or_ask_novice()` 里 `open_dialog()` **之前**先 `hud.set_stage(..., 0.0)`
   （先归零再弹，顺序不能反）
2. `_process()` 开头早退：

```gdscript
if _novice_ask != null and _novice_ask.is_open():
    return
```

### 3.6 [PITFALL] 传 0 秒后顶条显示「00:00」+ 满环

读作"已经超时了"，比不显示还糟。
`eve_command_bar.refresh()` 加分支：`time_total <= 0.0` 时隐藏环、文案改「不限时」、环进度归 0。

## 四、i18n 处理：本次一个新 key 都没建

`i18n/strings.csv` 已于 2026-08-11 冻结，新增 key 会让 `verify_i18n` 报英文缺失。

⚠️ **`T.t(key, fallback)` 也一样会触发** —— 只要 key 在 CSV 里不存在就算缺失。
所以本次新文案**全部改用中文字面量**，连 `T.t()` 都不包：

| 曾计划新增的 key | 实际做法 |
|---|---|
| `NOVICE_TITLE` / `NOVICE_BODY` | 中文字面量 |
| `BAR_UNTIMED` | 中文字面量 |
| `SHOP_ARMED_HINT` | 中文字面量 |
| `RESOLVE_SELL_HINT` | 中文字面量 |
| `PREP_UNTIMED` / `BATTLE_ESCALATE_UNTIMED` | 中文字面量 |

唯一动的 i18n 是**改既有 key 的值**（`DOSSIER_EMPTY_P`），不算新增。

## 五、影响面核查

| 路径 | 是否受影响 | 原因 |
|---|---|---|
| 桌面 / 网页单机 | 受影响（正常） | 弹框会弹，这就是需求要的 |
| 联机对局 | **不受影响** | `_untimed()` 对 `versus != null` 恒 false，弹框闸门也挡了 |
| 40+ 个 `verify_*` 探针 | **不受影响** | `RUN_STORE.session_active` 闸门 |
| 老存档读取 | 不受影响 | `novice_mode` 缺字段默认 `false` |

## 六、验收清单（需人工确认）

- [ ] **结算期卖对船**：进结算 → 拖第一艘去商店 → 确认卖掉的**就是拖的那艘**
      （重点测"本回合有舰船阵亡"的局，这是原 bug 的触发条件）
- [ ] **卖了之后 3D 收掉**：卖完场上不该还站着那艘船
- [ ] **钱数即时刷新**：「持有 N 星币」在卖船瞬间变化，不用等下一帧
- [ ] **备战席轨道不染橙**：结算期只有商店窗是橙色出售区，轨道不是
- [ ] **两段式点击**：点一下出档案 + 金边 + 「再点一次购买 ◆N」，第二下才扣钱
- [ ] **上膛态会清**：选了一张卡 → 刷新商店 / 进交战 → 金边应当消失
- [ ] **新手模式弹框**：从菜单开新局弹一次；局内重开（R）不再弹
- [ ] **不限时显示**：选新手模式后顶条显示「不限时」，没有满环、没有 00:00
- [ ] **战斗能结束**：新手模式开战后仍会因火力渐增而分出胜负，不会僵死
- [ ] **联机不弹框**：联机对局不应出现新手模式询问

⚠️ 另需自查两处既有断言可能被撞到：

1. `set_selling()` 加了第二个参数 → 若有验收脚本按单参调用/断言视觉，需复核
2. 顶条在 `time_total <= 0` 时不再显示 `00:00` → 若有断言文本，需复核
