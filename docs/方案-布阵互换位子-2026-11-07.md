# 方案：布阵期「互换位子」（拖到已有船的格子）

- 日期：2026-11-07
- 状态：**已实现**
- 触发：玩家反馈

> 玩家原话：「棋盘上的船需要能互换位子。现在需要三个步骤去调位子，太过于麻烦。
> 比如鲲鹏想跟死亡旋涡换位子，目前不能把鲲鹏直接拖到死亡漩涡上完成两个位子互换，
> 只能先把鲲鹏丢一边，然后去移动死亡漩涡去原来鲲鹏的位子，
> 最后再让鲲鹏去原来死亡旋涡的位子。」

---

## 一、改造前为什么是三步

`EveRunState` 里两条落地路径都把「这一格已经有船了」当硬错误：

| 路径 | 原行为 |
|---|---|
| `move_field(i, r, c)`（场上 → 场上） | `_cell_taken()` 为真 ⇒ `_deny("这一格已经有船了")` |
| `deploy_from_bench(i, r, c)`（备战席 → 场上） | 同上，且先撞 `field_limit()` |

提示层同样把它当错误：`preview_place` 返回 `ok = false`，
所以拖动时那一格**不高亮**、幽灵写「这一格已经有船了」——
玩家的合理反应就是绕路：先丢到空格，再倒腾两次。

---

## 二、改成了什么

### 2.1 语义

| 拖动来源 | 落点 | 结果 |
|---|---|---|
| 场上 | 空格 | 移动（原行为） |
| 场上 | 已有船 B | **A ↔ B 互换格子** |
| 场上 | 自己那一格 | 合法 no-op（不再报错） |
| 备战席 | 空格 | 上场（原行为） |
| 备战席 | 已有船 B | **A 进场，B 回 A 腾出来的那个备战席格** |
| 任何 | 出售区 | 出售（原行为，优先级最高） |

### 2.2 两条关键约束（都容易漏）

**① 互换不占新人口 ⇒ 必须跳过 `field_limit()`。**
满员（如 8／8）时互换是完全合法的（换人不换人数）。
若仍走原来的 `field.size() >= field_limit()` 判定，玩家满员时**恰恰换不了位**
——而那正是他最想换位的时候。判定顺序因此改为「先判互换，再判上限」。

**② 备战席互换不需要「备战席有空位」这个前提。**
被顶掉的 B 回的是 **A 腾出来的那一个格**，备战席数量不变，
所以永远放得下。⛔ 别给它加 `bench.size() < BENCH_SLOTS` 的前置检查。

### 2.3 提示必须点名

落点提示从「移动到这里」改成 **「与 死亡旋涡级 互换位置」**。
理由：互换会把另一艘船顶去备战席（位置变了、名额没变），
只说「移动到这里」玩家看不出这一格有船，也不知道自己的操作把谁挪走了。
这是整条链里**唯一能提前告知**的地方。

## 三、附带修的一个手感问题：吸到船体

### 3.1 问题

上一轮把布阵态舰船放大到 3 倍（`BOARD_EXAGGERATION`），实测：

| | 世界船长 | 折算格数 | 屏幕投影 |
|---|---|---|---|
| 护卫 kestrel | 1.59 单位 | 0.27 格 | 86 × 64 px |
| 战列 abaddon | 6.84 单位 | **1.14 格** | 108 × **284 px** |

（数据出自 `docs/方案-准备阶段棋盘模式-2026-11-07.md` 7.3 节）

**船体在屏幕上远大于它占的那一格。** 而落点判定只看「指针射线打在棋盘平面的哪一格」。
⇒ 玩家按直觉「把 A 按在 B 的船体上」松手时，指针常常落在 **B 的邻格**（甚至空行），
A 被放到旁边 —— 看起来就是「互换没生效」，正是这次要消灭的现象。

### 3.2 做法

`EveDeployController._drop_cell(pos)`：

1. 先按格判定。指针所在格**有船** ⇒ 就是它（最具体，包含"空格"语义）。
2. 指针所在格是空的 ⇒ 遍历我方舰船，取 `EveShipVisual.hull_world_aabb()`
   （只含 `Model_*` 子树，不含护盾椭球与血条），投影成屏幕矩形；
   **指针落在谁的轮廓里，目标就算谁的格子**。
3. 都没有 ⇒ 退回格判定。

`update_drag`（高亮 / 提示）与 `end_drag`（真正执行）**共用这一个入口** ——
沿用项目既有的同源原则：高亮就是承诺，只能有一处决定"落在哪"。

⛔ 只在准备阶段吸：结算期棋盘已收起、舰船只是画面残留，吸过去会把「拖去出售」弄钝。

### 3.2.1 两条「不许吸」的红线

两条都是实机想得到、必须写死的：

| 红线 | 不写会怎样 |
|---|---|
| 指针**不在棋盘上**（格号 `x < 0`：备战席 / 商店 / 画外）⇒ 不吸 | 「拖回备战席」会被船体吸走，变成"挪回棋盘"——功能直接倒退 |
| 指针格与那艘船的格子**相邻**（±1 行/列）⇒ 不吸 | 「把这艘挪到它旁边」是最常见的动作，而相邻格常常正好被船体盖住；吸过去就变成互换，手感比"不吸"更糟 |

只有 **隔了 ≥2 格** 还落在船体轮廓里，才说明玩家真的是在指那艘船
（大战列的船艏离它自己的格心就有 2~3 行，那正是他按下去的地方）。

### 3.2.2 实测（真链路，`kestrel@(9,2)` 拖到 `abaddon@(9,7)`）

| 指针位置 | 按**格**判定 | 按**吸船**判定 | 期望 |
|---|---|---|---|
| 战列**船艏**（离格心 2 行） | (7, 7) ❌ | **(9, 7)** ✅ | 吸住 |
| 战列格心 | (9, 7) | (9, 7) | 一致 |
| 战列正下方一格 (10,7) 中心 | (10,7) | (10,7) | **不许吸** |
| 备战席带 (400,800) | (—) | (-1,-1) | **不许吸** |

第一行就是这次要消灭的现象：**按格判定会差 2 行**，玩家松手后船落在别处。

真拖放结果：`end_drag` → `kestrel@(9,7)` / `abaddon@(9,2)`，上场仍 2 艘，
拖动中的幽灵提示 = 「与 地狱天使级 互换位置」。
对照图：`docs/img/swap-before.png` / `swap-after.png`。

### 3.3 已知取舍（如实记录）

**间距 ≥2 格、且被船体盖住的空格，吸不到。**
比如某一列上站着一艘战列，它上方 2~3 行的空格在屏幕上被它的船体盖住 ⇒
指针放上去会被吸到那艘战列身上（变成互换），而不是落进那个空格。
相邻格已被红线②保护掉，所以受影响的只剩「隔 2 格以上」的那几个。

判断：**可以接受**，因为玩家在这一带看到的就是那艘船的船体，
「指着船 = 指给船」比「指着船却落到看不见的邻格」更符合直觉。
要往那一带放船，把指针移到该格露出来的部分，或者先把那艘船挪走。

另一条可选路线（**没做**）：只在「指针离目标船格中心比离空格中心更近」时才吸。
推演下来它等于把吸船关掉 —— 玩家按在船体上半部时，
空格的格中心恰恰就在指针正下方，永远"更近"。
真正起保护作用的是红线②（相邻不吸），不是距离比较。

## 五、验收清单

| 验什么 | 怎么验 |
|---|---|
| 场上互换 | 拖 A 到 B 身上松手 ⇒ 两艘**立刻**对调，上场数不变 |
| 一步完成 | 全程只用一次拖动（不是三步） |
| 点名提示 | 悬停在 B 上时幽灵显示「与 XXX 互换位置」 |
| 高亮一致 | 高亮的格子 = 松手后真正落到的格子 |
| 满员互换 | 上场 8／8 时照样能换（不该提示"上场已满"） |
| 备战席互换 | 拖备战席的船到场上某艘身上 ⇒ 进场的落在该格，被顶掉的回腾出来的那个备战席格 |
| 不被误吞 | 拖到空格仍然落在空格（只有被船体盖住的空格会被吸走，见 3.3） |
| 结算期 | 打捞阶段拖船去卖，仍然是"卖"，不出现互换提示 |
| 开战 | 互换后按开战，站位与视觉一致 |

`tools/verify_review_fixes.gd`（`_t_swap_cells`）覆盖前四条的数据层与文案层。
