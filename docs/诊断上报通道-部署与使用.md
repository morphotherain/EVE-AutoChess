# 诊断上报通道：部署与使用

> 2026-11-07 建立。起因：玩家报告荣耀平板 GT 闪退，但"闪退"两个字什么都说明不了，
> 而要玩家连电脑抓 logcat 不现实 ⇒ 让游戏自己把现场发回来。
> 相关分析见 `玩家反馈-荣耀平板GT卡顿闪退-2026-11-07.md`。

## 一、链路

```
游戏内（EveReport autoload）
   │  HTTP POST application/json
   ▼
http://49.233.138.141/report          ← Caddy（:80，网站唯一允许 POST 的入口）
   │  reverse_proxy 127.0.0.1:27102
   ▼
eve-report.service（node，只监听回环）
   │  落盘
   ▼
/var/lib/eve-reports/YYYY-MM-DD/HHMMSS-xxxxxx.json
```

与热更同机同通道（`EveUpdater.META_URL` 用的是同一台机器的 http）。
⚠️ **为什么不用 https**：老客户端的热更地址写死在 `http://IP`，Caddy 那边明确要求
"这个 IP 入口不许跳转"；上报走同一条路最省事，也不会踩到域名证书的坑。

## 二、客户端行为

| 触发 | 时机 | 玩家看到什么 |
|---|---|---|
| **崩溃上报** | 启动时发现 `user://run.flag` 残留（= 上次没走完退出流程） | 弹一次「上次没有正常退出 / 发送 / 不用了」 |
| **手动反馈** | 主菜单**点右下角版本号** | 弹「发送诊断信息 / 发送 / 取消」 |

- 同一个现场**只问一次**：`user://report_last.txt` 记着那一次启动的时间戳，发过就不再追问。
  ⚠️ 不能用「删 run.flag」来代替这件事 —— marker 还兼着崩溃检测的职责，这一局再崩一次还得认得出。
- 玩家点「不用了」= **一个字节都不发**。
- 发送内容：设备型号 / 屏幕与窗口尺寸 / 逻辑视口 / max_fps / MSAA / FXAA / 当前场景 /
  静态内存 / 版本号 / `user://device_metrics.txt` / **日志尾部 120 行（64KB 封顶）**。
  ⛔ 不含存档、不含账号。
- 网络不通：落 `user://report_queue/<ts>.json`，下次启动补发 1 条；队列最多 8 条、14 天过期。

### 日志为什么要"快照"

引擎在**任何 GDScript 跑起来之前**就用 WRITE 打开 `user://logs/godot.log`（截断）。
所以崩溃当次的日志活不过重启 —— 等我们启动去读，读到的是本次启动的空日志。
真正能留下的现场是 `EveBoot` 在 `NOTIFICATION_APPLICATION_PAUSED` 那一刻抓的
`user://logs/last_session.log`，而"切后台 → 返回"这个窗口正好是引擎 #124903 那条崩溃的触发条件。

## 三、服务端

| 项 | 值 |
|---|---|
| 代码 | `tools/report/eve_report_server.js`（无依赖，node 22） |
| 服务 | `eve-report.service`，`User=www-data`，`Restart=always` |
| 监听 | `127.0.0.1:27102`（对外只有 Caddy 一个洞） |
| 落盘 | `/var/lib/eve-reports/<日期>/<时分秒>-<6hex>.json` |
| 限制 | 单条 300KB（超了 413）、同 IP 20 条/分钟（超了 429）、非 `POST /report` 一律 404 |

Caddy 那边有个**必须注意的坑**：原来的 `@bad not method GET HEAD → 405` 在指令顺序上
**排在 `handle` 之前**（Caddy 的固定顺序里 `respond` 先于 `handle`），
如果不把 `/report` 从 `@bad` 里排除掉，POST 会在到达反向代理之前就被 405 掉。
现在的写法是：

```
@bad {
	not method GET HEAD
	not path /report
}
respond @bad "method not allowed" 405

@report path /report
handle @report {
	reverse_proxy 127.0.0.1:27102
}
```

## 四、部署步骤（换机 / 重建时照这个来）

```bash
# 1) 放代码
mkdir -p /opt/eve-report
#    把 tools/report/eve_report_server.js 传上去（面板上传 / scp 均可）
node --check /opt/eve-report/eve_report_server.js

# 2) systemd
cat > /etc/systemd/system/eve-report.service <<'EOF'
[Unit]
Description=EVE diagnostic report endpoint
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/node /opt/eve-report/eve_report_server.js 27102
Environment=OUT_DIR=/var/lib/eve-reports
Restart=always
RestartSec=3
User=www-data
Group=www-data
NoNewPrivileges=true
ProtectSystem=full
ReadWritePaths=/var/lib/eve-reports

[Install]
WantedBy=multi-user.target
EOF
mkdir -p /var/lib/eve-reports && chown www-data:www-data /var/lib/eve-reports
systemctl daemon-reload && systemctl enable --now eve-report

# 3) Caddy：按第三节那两段改 /etc/caddy/Caddyfile，然后
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
systemctl reload caddy

# 4) 验收（在任意一台机器上）
curl -s -X POST http://49.233.138.141/report -H 'Content-Type: application/json' \
     -d '{"kind":"selftest"}'
# 期望：{"ok":true}
curl -s -o /dev/null -w '%{http_code}\n' http://49.233.138.141/update/version.json
# 期望：200（别把热更通道碰坏）
```

## 五、看收上来的东西

```bash
ls -lR /var/lib/eve-reports | tail -20
cat $(ls /var/lib/eve-reports/*/*.json | tail -1) | head -c 2000
```

`/report/health` 只在服务器本机可达（`curl 127.0.0.1:27102/report/health`），
**故意不对公网开放** —— 别把它加进 Caddy 路由。

## 六、已知限制 / 待办

- ⚠️ **这台服务器免费期到 2026-11-30**。到期后要么续、要么把上报端点搬到别处；
  客户端里 `ENDPOINT` 是写死的常量，换域名要发版（或走一次热更）。
- ⚠️ 只有"上次没正常退出"才会自动弹窗。**被系统静默杀掉且当时已经落盘日志**的情况能覆盖；
  如果是"点开就闪退、根本没进到主菜单"，`run.flag` 还是上一局的残留，靠时间戳能看出来。
- 目前**没有**"玩家写一段描述"的输入框：v1 只要发/不发。等确认通道稳定了再加。
- 磁盘只增不清。一条典型上报 20~60KB，几十条无所谓；上千条时要加清理脚本。
