# 玩家反馈：荣耀平板 GT（8+256）卡顿 + 频繁闪退

> 2026-11-07 立档。**当前状态：只做了分析与取证方案，未改任何游戏代码。**

## 一、一句话结论

这台的硬件不是"跑不动"，是**我们在 5.15 MP 的 3:2 屏上按 1920×1080 的预算在跑，而且一行帧率上限都没写**；
闪退则大概率不在我们的代码里，而是 **Godot 4.7.2 Android 的切后台 teardown 崩溃** + 满载发热这两条。
⇒ 处置分三层：玩家端设置（今天就能试）、工程端 P0 三条（改完立刻见效）、引擎侧跟版本。

## 二、设备事实

| 项 | 值 | 对游戏的影响 |
|---|---|---|
| 型号 | 荣耀平板 GT / ROL-W60 | — |
| SoC | 天玑 8350 至尊版（1×A715 3.35G + 3×A715 3.2G + 4×A510） | 中高端偏上，CPU 不是瓶颈 |
| GPU | **Mali-G615 MC6** | 移动 GPU 里属于"带宽紧、fill rate 低"的一档，最怕高分辨率 + MSAA |
| 内存 | 8 GB（与 GPU 共享） | 够，但切后台容易被 MagicOS 回收 |
| 屏幕 | 11.5" **2800×1840**（3:2），最高 **144Hz**，LCD | ★ 关键：像素量是 1080p 的 2.4 倍 |
| 系统 | MagicOS 9.0（Android 15） | 有省电模式、游戏管家、后台管控 |

`[SRC]` 荣耀官网参数页 honor.com/cn/tablets/honor-pad-gt/spec + 京东商品页规格。

## 三、为什么"必然卡"——把数字摊开

```
2800×1840 = 5.15 MP          （1920×1080 = 2.07 MP，即 2.49 倍）
60 fps  → 309 Mpix/s
144 fps → 742 Mpix/s
```

而我们当前的渲染配置（`project.godot`）：

```
renderer/rendering_method.mobile = "gl_compatibility"   ← GLES3，对 Mali 最稳，但也最慢
anti_aliasing/quality/msaa_3d = 1                       ← 2× MSAA
anti_aliasing/quality/screen_space_aa = 1               ← FXAA 全屏后处理
eve_battle_arena.gd:446  env.glow_enabled = true         ← glow = 多级模糊链，全屏跑
Engine.max_fps                                          ← ★ 全工程 0 处设置 = 不封顶
```

**没有任何一处写 `Engine.max_fps`**（全库 grep 结果为空）。Godot 在 Android 上默认 vsync 跟随屏幕，
系统若给到 120/144Hz，我们就照着 120/144 去画 5.15 MP + 2×MSAA + FXAA + glow。
Mali-G615 MC6 的 fill rate 撑不住这个组合 `[EST]`，结果就是：帧率掉到 20~30 → GPU 长期满载 →
发热 → 系统降频 → 更卡。玩家说的"卡顿"和"发烫"是同一个原因。

★ 顺带一个反直觉结论：**别去打背景贴图的主意**。
4096×4096 等距柱状图横向铺满 360°，相机水平 FOV 约 65°，
屏幕上能用的只有 `4096 × 65/360 ≈ 740 px`，再放大到 2800 px 显示 —— **已经被放大 3.8 倍**。
再降分辨率只会更糊，不会更快。真正该做的是**给它开 mipmap**（现在是 `mipmaps/generate=false`），
否则每像素随机采样 4K 纹理，Mali 的纹理缓存会被打穿。

## 四、闪退：三个候选，先分清再动手

| # | 候选 | 判据（logcat 关键行） | 处置 |
|---|---|---|---|
| A | **引擎 bug**：Godot 4.7.x Android 渲染线程 teardown 竞态 | `signal 6 (SIGABRT)` + `FORTIFY: pthread_mutex_lock called on a destroyed mutex` + 栈里有 `GodotRenderer.onRenderThreadExiting` | 只能等引擎修（见下） |
| B | 显存/内存压力被系统杀 | `lowmemorykiller`、`OutOfMemoryError`、`onTrimMemory` 后立刻消失 | 降分辨率/MSAA（同第三节） |
| C | Mali 驱动超时 / 上下文丢失 | `GLES_mali`、`EGL_BAD_CONTEXT`、`call to OpenGL ES API with no current context` | 同上；严重时降级渲染 |

★ 候选 A 已经有官方 issue，且**和我们完全同构**：
[godotengine/godot#124903](https://github.com/godotengine/godot/issues/124903)（2026-10-27，仍 open）
- 机型：Pixel 8，**ARM Mali-G715**，**Android 16**
- 渲染器：**gl_compatibility (OpenGL ES 3.2)** —— 同我们
- 版本：**4.6.3 与 4.7.2 都复现**，升级引擎没用，只有触发点位置变了
- 触发：**切到后台 / 从桌面重新进入**
- 已排除：换渲染器（Vulkan 一样崩）、换线程模型（single-threaded 一样崩）
⇒ 说明是 Android pause/destroy 时序里的共享竞态，不是 GPU 驱动问题。

**这条如果对上了，含义很明确**：玩家"玩着玩着切出去看一眼微信/锁屏，回来就闪退"，
跟我们写得好不好没关系，4.7.2 上就是会崩。得跟 4.7.3+ / 4.8 的修复。

## 五、玩家端：今天就能试的 8 条（按收益排序）

`[SRC]` 荣耀官方支持页 zh-cn00406924 + 荣耀社区答答团回复（club.honor.com 多帖）。

1. **电池 → 关闭省电/低电量，电池使用模式设「性能」**（省电模式会直接砍 GPU 频率）
2. **设置 > 应用 > 游戏管家**：开开关，把「EVE 自走棋」加进去（游戏加速 / 屏蔽误触）
3. **清后台**：系统管家 > 应用启动管理，把不需要自启的关掉
4. **存储留 ≥20%**（官方原话：低于 10% 系统性能急剧下降）
5. **设置里搜「8T LTPO 单扫模式」，有就关**（LCD 的 GT 可能没有，搜不到跳过）
6. **应用信息 > 存储 > 清除缓存**；⛔ **千万别点「删除数据」**（单机存档会一起没）
7. **别边充边玩**，机身烫的时候先凉一会儿（过热保护会降频）
8. **系统更新到最新 MagicOS**（MagicOS 9 早期版本对天玑 8350 的调度有数个补丁）

## 六、工程端：建议改动（按收益/风险排）

> **2026-11-07 落地状态：P0-1 / P0-2 / P0-3 已实现（版本 0.14.10.5.36）。P1、P2 未动。**
> 三条都写在 `scripts/core/eve_boot.gd`，且全部被 `OS.has_feature("mobile")` 守卫，
> 桌面 / 网页行为零变化（出图基线不受影响）。

### P0-1 封顶帧率（改 1 行，收益最大）
启动时（`scripts/core/eve_boot.gd` 的 `_ready()`，已有 mobile 分支）：

```gdscript
# [WHY] 5.15MP + MSAA2x 在 Mali-G615 上撑不到高刷；不封顶 = 系统给多少就画多少，
#       结果是满载→发热→降频→更卡。60 足够，且留出余量给 glow/粒子。
Engine.max_fps = 60
```

### P0-2 移动端关掉 MSAA 与 FXAA
```gdscript
get_viewport().msaa_3d = Viewport.MSAA_DISABLED
get_viewport().screen_space_aa = Viewport.SCREEN_SPACE_AA_DISABLED
```
`[WHY]` 2× MSAA 在 tiler GPU 上是纯带宽税，5.15 MP 下最贵的一项；FXAA 是第二遍全屏采样。
在 2800 宽的屏上，PPI 291，关掉后锯齿肉眼几乎看不出。桌面仍保留工程设置里的 2×。

### P0-3 打开文件日志 + 异常退出检测（为了拿到证据）
```ini
[debug]
file_logging/enable_file_logging = true     ; → user://logs/godot.log（Android 同样有效）
```
再配一个 run marker（启动写 `user://run.flag`、正常退出删），下次启动若发现残留就提示"上次异常退出"，
把 `godot.log` 尾部 + `device_metrics.txt`（已有，`scripts/mobile/eve_device_info.gd`）一起上报。

★ **这里有个坑，不踩过会白做一次**：引擎在**任何 GDScript 执行之前**就用 WRITE 打开
`godot.log`（截断），所以崩溃当次的日志活不过重启 —— 等到我们启动时去读，读到的是本次启动的空日志。
真正能留下现场的是 `NOTIFICATION_APPLICATION_PAUSED` 那一刻抓的快照（`user://logs/last_session.log`），
而候选 A 的崩溃恰好就发生在"切后台 → 返回"这个窗口里，快照正好覆盖。
启动时若发现 `run.flag` 残留，就把快照尾部 40 行打到 logcat（`[prev]` 前缀），
将来接上反馈通道也能直接读这个文件。
`[WHY]` 玩家在千里之外，没有这个就只能靠猜。有了它，"A/B/C 三候选"一次就能分完。

### P1 3D 渲染缩放（需要实测）
```gdscript
get_viewport().scaling_3d_scale = 0.75   # 5.15MP → 2.9MP
```
`[TODO 实测]` Compatibility 渲染器对 `scaling_3d_scale` 的支持不保证；若无效，
只能给战斗场景套 `SubViewport`（当前全工程 0 个 SubViewport，3D 直接画在根视口上），
那是一次动相机的结构性改动，要单独立项。

### P1 背景天空盒开 mipmap
`assets/backgrounds/*-4096.png.import`：`mipmaps/generate=false → true`。
代价 +33% 显存（约 +16MB/张），换掉纹理缓存抖动与星空闪烁。

### P2 画质档位
把上面几条抽成 `低/中/高` 三档，首次启动按 `OS.get_model_name()` + 屏幕像素自动选档，
设置页给手动开关。⚠️ 现在全工程**没有任何画质设置项**（grep `画质|quality` 只命中伤害品质），
加档位等于开一个新系统，别顺手塞进这次修 bug 里。
