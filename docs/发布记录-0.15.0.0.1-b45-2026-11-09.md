## 二、修了什么

### 现象（玩家反馈）

- **只能买船**；
- 商店「↻ 刷新」「▲ 等级加速」「✦ 锁定加速列表」点了没反应；
- 战斗结算页「继续 · 下一节点」点了没反应（截图里的节点结算面板）；
- 打捞按钮同样点不动。

### 根因

b43 为解决「点过刷新之后按空格 = 又刷一次」的问题，加了**两道摘焦点**：

1. `eve_hud_root._ready()`：`viewport.gui_focus_changed → call_deferred("release_focus")`
2. `eve_battle_scene._input()`：按空格前先把焦点持有者的焦点释放掉

关键在于时机 —— `gui_focus_changed` 是在**鼠标按下那一刻**发出的，
此时 `BaseButton.press_attempt` 刚刚置位。释放焦点会连带把它清掉，
于是抬手时 `pressed` 不再触发。按钮的表现是「**按得下去、但没反应**」
（按下态照常绘制，所以看起来像没坏）。

一次探针（真 `Button` + `push_input` 灌鼠标事件）实测：

| 情形 | `pressed` 是否触发 |
|---|---|
| A 正常点击 | ✅ |
| B 按下后 `release_focus()` | ❌（b43 的线上行为）|
| C 按下后 `focus_mode = FOCUS_NONE` | ❌ |

⛔ C 也救不了：`set_focus_mode(NONE)` 在持有焦点时内部同样会释放焦点。

**为什么只有卡片还能点**：商店卡走的是 `gui_input`（不看 `press_attempt`），
刷新 / 加速 / 锁定 / 继续 / 打捞全是真 `Button` ⇒ 现象恰好是「只能买船」。

### 修法：不碰焦点，摘动作

新增 `scripts/ui/eve_input_guard.gd`：

- `detach_space_from_accept()` 把「空格」事件从 `ui_accept` 动作里删掉
  （`keycode` 与 `physical_keycode` 都判，防版本差异）；
- `static var` 幂等，可以重复调用；
- 用 `preload` 路径引用，**不注册 `class_name`**（注册表是引擎启动时定死的，热更改不了）；
- **只摘空格，回车与手柄 A 保留** —— `eve_confirm_dialog` / `eve_update_panel`
  会 `grab_focus()` 到按钮上等玩家敲回车，那是真需求。

调用点两处（幂等，重复调用无害）：

- `eve_main_menu._ready()` —— 启动后的第一个页面，全局生效；
- `eve_battle_scene._ready()` —— 覆盖「直接打开战斗场景」的调试 / 探针路径。

⛔ **为什么不直接改 `project.godot` 的 `[input]`**：那是 `project.binary`，
引擎启动时就读完了，热更 pck 挂上去也改不动它 ⇒ 只能运行时摘。

| 检查 | 结果 |
|---|---|

## 五、留给下一次的教训

1. **「按空格又点了一次」这类 bug，病因在 `ui_accept`，不在焦点。**
   摘动作是最小、最安全的改法。
2. **任何「在鼠标按下瞬间改焦点」的方案都会静默废掉 `pressed`。**
   包括 `release_focus()` 和 `focus_mode = FOCUS_NONE`。
3. **判定按钮坏没坏，要看 `pressed` 有没有发**，不能只看「点得下去」——
   按下态是独立绘制的，会骗人。
4. 本次是 b43 的回归，**当天发现、当天回滚**。教训是：
   上一个"修好了"的验证只验了「空格不再重复点击」，**没验「按钮还能点」**。
   以后改输入/焦点相关的代码，必须同时跑一次「点击正常」的对照。
