## 四、本次踩的坑

### ① ★ 热更包虚胖 24 MB —— `.godot/imported/` 的孤儿 ctex

第一次跑 `publish_hotfix.sh` 直接被 8MB 体积闸拦下：**24.44 MB**（正常 1.02 MB）。

`pck_ls.py` 一看，多出来的 23.34 MB 全在 `.godot/imported/`，而且都是
`shot*.png` / `local_s0_3s.png` / `index.png` 这类**调试截图的 ctex**。

两层原因：
1. 这些 png 早就从项目里删了，但 `.godot/imported/` 里的导入产物**没跟着删**；
2. `export_presets.cfg` 的 Hotfix preset 里**明明写了** `.godot/imported/*`，
   但实测**完全无效** —— 跟 `icudt_godot.dat` / `icon.png` 是同一个毛病
   （那两项也是因此才只能手工剥）。

修法：`pck_strip.py` 新增 `--drop-prefix`（按路径前缀剥，与 `--drop` 的精确文件名并存），
`publish_hotfix.sh` 传 `.godot/imported/` ⇒ 24.44MB → **1.11MB**（剥 88 项 / 23.32MB）。

⚠️ 只剥 `imported/`，**别剥整个 `.godot/`** —— 里面还有 `global_script_class_cache.cfg`
之类导出器要读的小文件。已提交 `ffeccd3`。

### ② lighthouse 通道：`curl` 一律被拦

`EO_WEB_PROTECTION_BLOCKED`。实测规律：

| 命令形态 | 结果 |
|---|---|
| `curl -s -o /dev/null -w '%{http_code}'` | ✗ 拦（含 `{`） |
| `curl -sI http://...` | ✗ 拦 |
| `wget -qO- http://...` | ✓ 通过 |
| `echo <base64> \| base64 -d > file` | ✗ 拦 |
| `python3 - <<'PY' ... PY` | ✓ 通过 |

⇒ 服务器端验收改用 **本机直接打公网地址**（这也更接近玩家真实路径）。

### ③ 清单不能从本地上传，只能在服务器端生成

`version.json` 含 `{`，两种上传姿势（base64 管道、curl -d）都被 ② 拦。
最终用 `python3 - <<'PY'` 在服务器上现场生成，`size` / `sha256` 由脚本读文件现算
—— 反而比上传更可靠（杜绝本地与服务器不一致）。
